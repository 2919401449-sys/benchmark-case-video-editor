# B-roll 匹配规则

在 `broll_index.json` 已经有描述和标签，且 `broll_analysis.json` 已完成多帧分析时使用本参考。

AI智能设计平台案例会额外载入 Skill 内的通用产品录屏库。它们在索引中标记为 `origin: skill_common_ai`，生产对接案例不载入。通用录屏的描述和标签来自随 Skill 保存的审核清单，不需要每次重新猜测内容；画面稳定窗口仍按本案例同样重新分析。

## 描述字段

每段 B-roll 至少保留：

- `source`：原素材绝对路径；
- `thumbnail`：单张代表画面；
- `storyboard`：覆盖素材前、中、后段的五帧故事板；
- `best_windows`：不同目标片长下的稳定时间窗口；
- `description`：客观描述画面中可见的人物、地点、动作和产品界面；
- `tags`：短标签，例如“公司外景”“设计师沟通”“效果图”“工地放样”。

不要根据文件名或单张截图臆测整段内容。至少查看五帧故事板；画面不清楚时标记 `needs_review`。

## 稳定片段选择

- 不再默认取素材正中间固定4秒。
- 对低分辨率代理帧估算全局位移、位移突变、清晰度、曝光和连续性。
- 分别为2.0、2.8、3.6、4.5秒窗口评分，优先采用与口播句长相近的最高分窗口。
- 素材足够长时，首尾各保留约0.8秒安全区；短素材宁可缩短片段，也不要强行带入按下录制键和停止录制时的抖动。
- 平滑推拉可以保留；惩罚的是位移方向和速度快速变化形成的抖动。

两个只读人工参考草稿显示：B-roll 中位时长约为3.2秒和3.94秒；多数片段会剪掉至少1秒开头，约七成至九成片段会剪掉至少1秒结尾。这些统计用于设置默认偏好，不是不可调整的硬规则。

## 覆盖率与连续性

- 两个参考案例的主 B-roll 轨覆盖率分别为42.4%和82.2%，A-roll 未覆盖比例分别为57.6%和17.8%。默认最低覆盖率设为50%，实际数量仍由有明确语义匹配的短句决定。
- 长段落按约每5.5秒一个视觉信息点选择候选，每段最多4个；普通镜头优先2.8–4.5秒，避免只增加大量一闪而过的碎镜头。
- 相邻 B-roll 之间的 A-roll 空档不超过1.5秒时，默认连成一个连续覆盖块。优先使用两个稳定窗口的首尾余量补齐空档。
- 如果稳定窗口没有足够余量，不向素材容易抖动的首尾硬扩；将两个稳定片段各平移不超过空档的一半，使它们相接。
- 1.5秒以上的 A-roll 空档可以保留，用于人物表情、身份建立、观点强调和节奏换气。
- 覆盖率只是下限和复核指标，不能凌驾于语义匹配、画面质量和素材复用上限。同一个源文件全片最多使用2次；没有足够素材时降低覆盖率并保留A-roll。

## 匹配优先级

1. 先把讲稿段落拆成短句，优先匹配当前短句明确提到的对象与动作，例如“效果图”“全员培训”“PPT谈单”。
2. 能解释抽象口播的具体画面，例如客户沟通、设计师操作、施工现场。
3. 公司环境、人物工作状态等通用氛围镜头。

候选分数由语义匹配、稳定画面质量和连续构图惩罚共同组成。相似素材不得再用文件名决定胜负。同一源文件第一次和第二次可以使用不同的稳定窗口；达到2次后从候选池移除，不允许以更高分数突破上限，同一段落内也不重复。

AI案例中，只要语义确实相关，优先使用通用酷家乐AI产品录屏；它们更适合解释“导入户型、选择风格、局部调整、一键出图、全屋漫游、效果增强”等产品动作。文件名及随Skill保存的manifest描述就是录屏内容标签，不要求模型重新理解整段录屏。最终时间线必须出现3–5条不同的通用录屏，默认目标4条；单纯提高匹配分仍不足3条时，按文件名标签替换语义最接近的客户B-roll窗口。每一条通用录屏在整支视频中最多使用1次，客户自身素材仍默认最多使用2次。任何一类素材达到各自上限后都不得重复突破。

具体动作的标签优先于宽泛场景。例如同时出现“效果图”和“工地指导书”时，优先 `construction_guidance`，而不是仅因标签更多选择电脑效果图。

避免连续重复相同构图。人物口播中的关键结论至少保留一段 A-roll，不要用 B-roll 覆盖整段。B-roll 放置位置应对齐对应短句，不使用固定的24%和62%锚点。

## 置信度

- `high`：画面直接对应讲稿中的明确对象或动作；
- `medium`：语义相关，但不是直接证据；
- `low`：仅作氛围填充，必须人工确认。

匹配输出应记录讲稿段落、对应短句、B-roll 源文件、入点、出点、匹配标签、语义分、质量分、综合分和置信度，并生成 `broll_matches.csv` 与 `broll_review.md` 供人工复核。

`broll_matches.json` 还必须记录 `max_source_uses`、`source_use_counts` 和 `sources_at_limit`。`edit_plan.json` 的 `b_roll_metrics.source_use_limit_respected` 必须为 `true`。
