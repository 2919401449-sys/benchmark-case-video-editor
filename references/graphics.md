# 信息图表生成与审核

## 目标

从已经确定的 V2 和 `edit_plan.json` 中选择 5–10 个真正适合视觉强化的内容点，生成透明图表覆盖层，并把它们作为单独轨道加入剪映草稿。图表不能替代口播事实，也不能展示 A-roll 中没有表达的数据。

## 为什么分成提案、审核、渲染三步

数字正则只能发现“28年”“3分钟”等表面信息，不能可靠判断“隔了一天”是否值得做图，也可能把“从事27年，到公司18年”误判成使用前后对比。因此：

1. `propose` 负责低成本找候选与建议模板；
2. Codex 或人工对照 V2 语义精简标题、标签和数值，并把确认项标记为 `approved`；
3. 动画模式运行 `sync`，根据原始逐词转写和 A-roll 保留片段换算出现时间；
4. `render` 执行已审核的模板和时间；
5. `attach` 新建 `edit_plan_with_charts.json`；动画模式另写包含 MOV 元数据的 `media_inventory_with_charts.json`。

`all` 命令也只执行提案并停在审核关口，不能绕过审核直接出草稿。自动候选即使含有数字，也一律标为需要复核。

审核由运行 skill 的 AI 完成，可以替换、补充或舍弃候选，不要求用户逐张确认。语义清楚且能回溯原话时继续执行；仅对无法从已有材料确定的事实提出问题。自动筛选支持同一人物的相邻句段，排除“一套”等普通计数，并避免把面积、金额和时长混成同一指标。AI 应通读最终字幕，防止遗漏具体案例、限定词和使用分寸。

## 四种模板

- `stat`：一个重点数字，例如“28年”“3分钟”“14万”。
- `comparison`：同一指标的前后变化，例如“7天 → 5天”。不要把两个无比较关系的数字硬放在一起。
- `list`：2–4 个并列要点，例如“展示关键空间角度、不一次给出完整效果图”。保留否定词。
- `flow`：2–5 个存在先后关系的步骤，例如“效果图 → 施工图 → 前期放样”。含“或者”的可选方案不能直接画成必经流程。

同一条信息只用一种模板。优先覆盖具体数据、明确对比和清晰流程；普通口号、模糊形容词、识别不确定的数据不自动做图。

## `chart_plan.json` 核心字段

每个 `charts[]` 项必须包含：

- `id`：项目内唯一，例如 `chart_01`；
- `section_ids`：事实来自哪些 V2/字幕段落；
- `template`：`stat`、`comparison`、`list` 或 `flow`；
- `title`：画面标题；
- `timeline_in` / `timeline_out`：图表在成片时间线上的出现范围；
- `source_text`：用于复核的原始表达；
- `status`：自动提案为 `auto_proposed`，核对无误后改成 `approved`。

顶层 `source_edit_plan_sha256` 把图表计划固定到这一次的 `edit_plan.json`。渲染和接入前会核对哈希、所引字幕句段、原话、图表出现时间，以及数字是否真实出现在原话中。剪辑计划或字幕一变，旧图表计划即失效，须重新提案、逐项审核。纯文字图表的概括也要人工核实，程序不能自动判断其语义是否准确。

模板内容字段：

- `stat` 使用 `value` 与 `caption`；
- `comparison` 使用 `columns` 与 `rows[{label,before,after}]`；
- `list`、`flow` 使用 `items`。

## 版式与时间规则

- 默认画布为 1920×1080，底部字幕安全区不放主要文字。
- 单张图一般显示 4.5–8 秒；数据较多的对比表可到 12 秒。
- 图表尽量均匀分布，不要为了凑够数量连续轰炸。
- 相邻图表默认不重叠。若必须叠加，需明确使用不同图表轨并人工审核。
- 标题尽量不超过 12 个汉字；列表单项尽量不超过 16 个汉字。
- 保留数字和单位，不为了版面改变数值含义。
- 列表、流程和前后对比的半透明底板随实际条目或行数收缩，底部保留适度内边距；不能用固定高度为少量内容留下大片空白。
- 可在 `chart_plan.json` 的顶层 `style.visual_theme` 设为 `editorial`，使用深色半透明侧边卡、编号步骤和双栏对比；省略该字段继续使用已验证的经典样式。视觉主题只影响渲染，不能改变已审核图表文字与口播锚点。当前 editorial 是供审核的第一版，不应自动推广到所有新案例。默认放在左侧；画面左侧有重要人物或产品时，可在单张图表上设置 `placement: right`。
- editorial 的前后对比数值框采用高不透明度深蓝／蓝色填充，尤其“使用前”不可透出复杂背景而失去辨识。`stat` 数字圆盘按出现顺序轮换五种装饰环造型（光环、刻度、双环、轨道、分段）；它们不是进度百分比，不能用缺口暗示虚构业绩。可在单张图表上使用 `ring_variant` 显式指定其中一种。
- 双语细线风格使用 `style.visual_theme: bilingual`。英文是同一条已审核中文事实的辅助翻译，不可增加结论或删掉“左右、不到、约”等限定语。必填字段：所有图表 `title_en`；`stat` 再填 `value_en,caption_en`；`list/flow` 填与中文逐项等长的 `items_en`；单行 `comparison` 填两项 `columns_en`，并在该行填 `label_en,before_en,after_en`。双语前后对比每页只放一行，更多数据拆页。
- 双语 `stat` 默认按出现顺序轮换光环、刻度、双环、轨道、分段五种造型，也可显式填写 `ring_variant`；验收检查不能只看颜色差异，轮廓结构也必须不同。中文标题、英文标题、主数值、英文数值、中文解释、英文解释使用固定的互不重叠纵向区域，任何文字层都不能进入相邻区域。
- 双语图表仅在布局审核要求模糊／居中或全屏对比时增加深色可读性蒙版。蒙版必须覆盖完整 1920×1080，包括顶部 Logo 区和底部字幕区，不绘制透明缺口或在 95–950 像素间截断；Logo 与字幕依靠更高图层保持清晰。

## 人物避让与全屏对比

动态图表完成 `sync` 后、`render` 前，运行 `python scripts/chart_layout.py prepare --work 工作目录`。它按图表区间内真正可见的 A/B-roll 切点抽帧，每个镜头首尾和约每秒一帧，输出 `layout_review/*_sheet.jpg` 和 `chart_layout_review.json`。

运行 skill 的 AI 必须查看全部抽样图，把每帧的人物头部、躯干、明显手势或关键产品屏幕填入 `protected_boxes`，坐标为 1920×1080 的 `[左,上,右,下]`。多矩形可以更准确保护不规则人物区域；确实没有重点对象才填 `[]`，未检查保持 `null`。这一步是图像理解，不做人物身份识别，也不要求用户手工圈选。移动明显时加密抽样。确认后标记 `status: approved`，执行 `chart_layout.py apply --work 工作目录`。

- 同张图表全程采用同一位置，按所有抽样画面的保护框判断，而不是只看第一帧。先尝试左右两侧，保留 30 像素缓冲；允许适量缩小，但不低于原尺寸 75%。
- 左右都放不下时，居中显示，底下加入独立的全画面模糊视频轨。模糊视频从实际 A/B-roll 切点生成，保持底层运动，静音，不改变原始口播及剪辑。它不是需要下载的剪映特效，也不是静止截图；在剪映可移除、裁切或替换，模糊强度改变需重新渲染。
- `comparison` 优先级最高：始终全屏大幅展示，底层模糊，标题、数值和两栏关系突出。顶部 Logo 与底部字幕保持清晰；每页至多两行，多行应拆图重新审核。
- 层级固定：A-roll → B-roll → 模糊背景 → 图表底板 → 圆环 → 数值/步骤 → Logo → 字幕。不能让按时间自动分轨把模糊层排到 Logo 上面。
- 位置、图表区间或剪辑改变后重做布局审核、渲染、接入；审核记录与计划保留哈希关联。检查真实视频背景上的合成预览，不仅检查透明图表。

## 系列角标

`scripts/branding.py` 在图表 `attach` 后执行。`assets/branding/` 只预设酷家乐和 AI 智能设计平台两个通用 Logo；客户 Logo 始终从当前案例素材文件夹读取。文件夹名包含 `AI智能设计平台` 时，左上为酷家乐 + 客户，右上为 AI 智能设计平台；包含 `生产对接` 时，左上显示“设计生产一体化|定制标杆工厂系列”，右上为酷家乐 + 客户。当前素材文件夹未标记时须显式传 `--case-type ai` 或 `production`。同目录有多张候选图片时使用 `--customer-logo`，不要猜选。

两个角标各输出一张 1920×1080 透明 PNG，作为两个全片长的独立 `graphics` 轨接入 `edit_plan_with_charts.json`，在剪映里可整体移动、隐藏、替换；图中文字和 Logo 像素不在剪映里逐字可编辑。Logo 周围必须保持透明，不绘制白色或其他颜色的矩形底板或描边。酷家乐图形及文字整体转为白色；AI 智能设计平台的文字转白，前面的渐变 AI 图案保留原色。酷家乐与客户 Logo 按透明可见区域裁去空边后统一到 55 像素可见高度（以原 46 像素固定放大 20% 后取整，不累计放大），中间以白色 `|` 分隔；由于字形比例不同，两者的宽度不强制相同。AI 平台 Logo 的可见区域距上边与右边均为 24 像素。对于四角近白的非透明客户 Logo，会在内存中去掉与画面外缘相连的白底，绝不修改原文件。生产对接类型的左上系列文字蓝色条幅仍按参考样式保留——它是文字标题，不是 Logo 底板。角标止于画面顶部约 79 像素，不应压住下方从 110 像素开始的图卡标题。客户 Logo 若自带小标语、但成片只需主标识，可在个案命令中指定 `--customer-logo-crop 左,上,右,下`，不修改源图。

## 剪映可编辑性

透明 PNG 会作为独立“信息图表”视频轨加入剪映，能整体移动、缩放、隐藏、替换和修改时长。PNG 内部文字、圆环、表格和箭头已经合成，不能在剪映里逐项改字或改颜色。需要改内容时，编辑 `chart_plan.json` 后重新运行 `render` 和 `attach`。

`propose --motion` 启用动态模式。四类模板和逐项口播同步已接入 `chart_pipeline.py`，实现位于 `chart_motion.py`。省略 `--motion` 时仍可生成静态 PNG。动画基础路径已在 Windows 剪映专业版 11.5.0 完成打开、预览和实际 MP4 导出验证。

## 逐项口播同步

每个图表添加 `cues`。每个锚点包含 `key`、`section`、`quote`；`quote` 必须是对应当前字幕中的实际短语，而不是图表概括后的标签。同一句内短语重复时填写从 1 开始的 `occurrence`。

- `stat` 使用 `key: value`。
- `list` 和 `flow` 使用 `item_1`、`item_2` 等。
- `comparison` 使用 `row_1_before`、`row_1_after` 等，每个单元格按各自口播独立出现；口播先说使用后时，也先显示使用后的数值。

例如：`{"key":"value","section":11,"quote":"三分钟"}`。流程标签可以写“结合施工图沟通”，锚点引用原话“施工图”。

`sync` 从 `transcript.json` 提取保留源片段内的逐词时间，统一繁简与中文数字，再对齐已校正字幕。锚点两端必须匹配，内部字符覆盖至少 65%；无法可靠对齐时写入 `chart_sync_report.json` 并停止渲染，不以字数比例伪装成精确同步。可以改用同一句实际说出的清晰短语，必要时复听。时间量化到成片帧率，ASR 本身可能仍有偏差。

标题和面板先出现，数值、步骤再跟随口播淡入。句尾对比来不及读完时，两个数值可从该对比短句起一起显示；原词时间与可读性调整分别记录，不延伸覆盖下一位人物。最后一项至少显示 1 秒，图表整体尽量保留 5–6 秒。不能满足时调整内容或引用有连续语义的相邻句段。

检查 `chart_sync_report.md` 后运行 `render`、`attach`。内容或锚点改变后重新 `sync`、`render`、`attach`；原转写或剪辑发生变化时旧同步结果失效。

## 动画兼容性与接入边界

已验证两条路径：

- 圆环绘制：本地生成透明 ProRes 4444 MOV；面板、圆环与数值分层。天数、金额等数值使用完整装饰圆环，不捏造百分比。可调整各层位置、大小和时长，图中文字需重新生成。
- 表格、列表和流程：面板、数值或步骤分别生成透明 PNG，使用剪映原生透明度和位置关键帧控制入场。箭头跟随下一个步骤出现。文字并非剪映可编辑文本。

导出器接受 `tracks.graphics[].keyframes`，每项为 `property`、`time`、`value`。`time` 是相对该图表片段起点的秒数。已实测 `alpha`（0–1）和 `position_y`；`position_x`、`uniform_scale`、`rotation` 已接入但尚未做界面视觉验收。位置采用底层草稿库的归一化坐标，不是像素。本次 `position_y=-0.035` 到 `0` 对应约 38 像素的入场位移。

MOV 等动态图表需在素材清单 `graphics[]` 中登记 `path`、`width`、`height`、`duration_seconds`，并设置合法的源入出点。关键帧时间不得超过片段时长。静态图表不填写 `keyframes` 时行为不变。

本次 1080p、25 fps、8 秒透明 MOV 约 69 MB；这是本地磁盘素材体积，不等同于网络流量或 token 用量。复杂图形可预渲染，简单逐项显现优先使用分层关键帧；无需为此强制引入新的大型渲染框架。

早期 20 秒兼容性示例在工作区 `video-editing-work/motion-compatibility-test/`，其中数据与背景口播未做同步。接入后的九鼎示例位于 `video-editing-work/jiuding-motion-v11/`，使用实际 V2 和原始逐词时间。不要把早期样片作为正式案例发布。

## 验收

打开 `chart_render_manifest.json` 中 `contact_sheet` 指向的检查图，逐张检查：

- 数字、单位和使用前后方向正确；
- 没有文字截断、溢出或字号过小；
- 透明区域正常，面板不会完全挡住主体人物；
- 不压住底部字幕；
- 图表数量在 5–10 张，且分布不过密；
- `edit_plan_with_charts.json` 的 `chart_metrics.review_required` 为 `false`。
- 先用新草稿名做明文结构检查，再导入剪映检查透明度、层级、字幕遮挡和同步；不要覆盖已经确认的旧草稿。
