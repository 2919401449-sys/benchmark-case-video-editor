# A-roll：从真实口播生成 V1 和 V2

## 核心原则

V0 只是一份采访后形成的背景资料，不再作为剪辑文稿。客户可能一部分照读、一部分自由发挥，因此逐人判断“照稿或自由发挥”仍会出错。唯一可靠的内容来源是 A-roll 实际说出的内容。

## 人物归属

多人素材可以混放在同一个 `A-roll` 文件夹。第一版不启用人脸或声纹识别，避免模型过重、部署复杂和误识别风险。

使用 `speaker_map.json` 做轻量映射：

```json
{
  "speaker_priority": ["周总", "包姐", "设计师甲"],
  "sources": {
    "C001.MP4": "周总",
    "C002.MP4": "周总",
    "C003.MP4": "包姐"
  }
}
```

`speaker_priority` 按职位从高到低排列。一个人可以对应多个文件。若没有映射，程序会把每个文件名临时视为一个人物，这只适合单人或一次性测试。

## V1：转写、清理、去重

1. 本地转写全部 A-roll，保留文件路径、起止时间和词级时间码。
2. 按人物合并片段，但保留每句话来自哪个文件以及原始时间范围。
3. 删除“重来、等一下、后期会剪吗”等现场指令和无内容的开场语气词。
4. 比较同一人物的句段。内容高度相似或一段明显包含另一段时，视为重复拍摄，只保留转写置信度较高、表达较完整的一次。
5. 可用 `transcript_corrections.json` 修正“酷家乐、AI、PPT、SU”等专有名词和明确同音错字。不得用它补写客户没有说过的话。
6. 输出 `script_v1.json`、`script_v1.md` 和 `script_v1_dedup_report.json`。

V1 的每句话必须满足：

- `origin` 等于 `transcript`；
- 有 `speaker`；
- 有 `source`、`source_in`、`source_out`；
- V0 的句子不会进入 V1。

## V2：按完整语义段删减

V2 从 V1 中选择句子，不拼接词语，不改写句意：

1. 优先保留可靠的业务数据；同一人物重复表达同一个数据时，只保留信息更完整的一次，例如“14万”和“十四万”不能占两次篇幅。任职年限、“第二天”、“一套”等不等于业务成果，明显识别错误的百分比也不能强制保留。
2. 先从人物自我介绍中的董事长、总裁、副总裁、总经理等职务判断最高职位者，再用 `speaker_priority` 处理同级情况。最高职位者必须是全片出场时间最长的人。
3. 其他人物与主讲人主题重复时，优先删除其他人物的重复表达；次要人物的独有案例、结果和具体数据可以保留。
4. 成交、定金、效率提升、客户反馈等结果性内容提高优先级。
5. 每个人至少保留一句，避免多人案例变成单人视频。
6. 同时检查两个目标：可见字符 1500–1800 字；素材真实时间至少 5 分钟，默认给成片保留到 6 分 30 秒。程序按最长成片时长预留约 6 秒剪切缓冲。
7. 信息分只用于挑选候选，不能直接把高分句子零散拼在一起。对于以“他、所以、因为、另外、就是”等开头的依赖句，必须补入必要前文；以“因为、但是、这样的话”等未完成连接词结束时，必须补入后文。
8. 两个已保留句段之间只缺一个连续句段时，默认把中间句补回来。超出时长后，删除完整的低价值连续段，不再从段落中间打洞。
9. 普通单句不能成为孤立段落。自我介绍、明确数据结论、前后对比和总结句可以独立成段。
10. 自动初选后，AI 必须通读 V1，以普通观众能否听懂为标准创建 `v2_editorial_plan.json`，不能只依赖连接词检测。计划示例：

```json
{
  "schema_version": 1,
  "max_secondary_ratio": 1.35,
  "blocks": [
    {
      "speaker": "周总",
      "orders": [1, 2, 3, 4],
      "reason": "完整说明公司背景和客户痛点"
    },
    {
      "speaker": "设计师甲",
      "orders": [20, 21, 22],
      "reason": "完整保留一个有结果的客户案例"
    }
  ]
}
```

11. 每个 block 原则上使用连续句号；中间只有“稍等、重录、后期剪掉”等现场口令时可以跳过。程序会拒绝普通内容上的无解释跳跃。
12. 除最高职位者外，计算每人的真实素材时长。`最长 ÷ 最短` 必须不大于 `1.35`。无法满足时，优先删减较长者的低价值完整段，或给较短者补充独有案例；不能拆掉句首原因或句尾结果来凑秒数。
13. 输出 `script_v2_coherence_report.md`。存在 `dependent_start`、`incomplete_end`、语义计划不合格或人物时长超差时，不得进入最终草稿。

## 生成 A-roll 时间线

V2 已经来自转写，并携带原素材时间码。`align` 应直接复制这些时间码，只在首尾加入很小的安全缓冲，不再把 V2 文字与 A-roll 做第二次模糊匹配。这样可以避免识别错字导致选中另一遍口播。

只有旧项目缺少 V1/V2 时间码时，才使用全局文本模糊匹配作为兼容路径。

## 人工复核重点

- `speaker_map.json` 是否把每个文件分给了正确人物；
- 去重报告是否误删了两段“主题相似但信息不同”的内容；
- 专有名词纠错是否只改错字，没有改变原意；
- 可靠且与业务结果有关的数据是否仍在 V2；
- V2 是否达到 5–6.5 分钟，最高职位者是否最长，其他人物最长/最短是否不超过 1.35；
- V2 每一段单独朗读时是否有完整主语、前因和结果；相邻段落是否发生无解释的主题跳转。
